# Правило: миграции БД

Применяется в репо с SQL-миграциями (`migrations/*.sql`) и PR-flow / несколькими параллельными сессиями. В репо без миграций — no-op.

- **Новые миграции — timestamp-префикс:** `YYYYMMDDHHMMSS_slug.sql` (`echo "$(date -u +%Y%m%d%H%M%S)_<slug>.sql"`). НЕ последовательный `NNN_`.
- **Почему:** последовательный номер — ОБЩИЙ счётчик. N параллельных сессий/веток берут «следующий» номер независимо и коллизят. У timestamp'а каждая сессия свой префикс → коллизий нет, порядок применения хронологический.
- **Legacy `NNN_*` не переименовывать** — сломает журнал применённых (`schema_migrations` ключом по имени файла). Заморозить на текущем максимуме; всё новое — timestamp.
- **DDL идемпотентен:** `CREATE TABLE IF NOT EXISTS`, `ADD COLUMN IF NOT EXISTS`, `DROP CONSTRAINT IF EXISTS`+`ADD`. Падать на повторном прогоне нельзя.
- **Энфорсер — тест гигиены:** формат (`NNN`≤заморозка | `timestamp`), уникальность префикса, запрет нового `NNN`, идемпотентность. Добавь тест гигиены миграций в свой репозиторий.
- **Факт применения журналируется** (файл, sha256, когда, кем); приложение само не применяет — только сверяет и логирует расхождения.
