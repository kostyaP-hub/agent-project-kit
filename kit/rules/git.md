# Правило: git

- **Никогда** не делай force-push без явной просьбы.
- **Никогда** `git commit --amend` по уже запушенным коммитам — делай новый коммит.
- **Никогда** не пропускай pre-commit хуки (`--no-verify`) без просьбы.
- `git reset --hard`, `git checkout --`, `git clean -fd` — деструктивны: не запускай без подтверждения.
- Один логический шаг = один коммит (детали — `commits.md`).
- Перед записью в чужой репо — `git remote get-url origin`. Если namespace origin отсутствует в `owned_namespaces` из `~/.ctx/config.json` — НЕ писать.
- Сообщение коммита объясняет **почему**, а не **что** (что видно по диффу).
- Если pre-commit хук упал: исправь причину, пере-stage, сделай **новый** коммит (не amend).

## Worktree-ссылки в git
- Worktree создавай **внутри `<repo>/.worktrees/<branch>/`**, не в глобальной директории (детали — `worktree.md`).
- Добавь `.worktrees/` в `.gitignore` репо (один раз).

## Топология репозиториев (стандарт §5)
- **Отдельный репо**, если верно хотя бы одно: свой деплой-таргет или рантайм; свой владелец или внешний коллаборатор; свой релизный ритм; свои секреты. Иначе — папка внутри существующего репо. Родственные прототипы — в один workspace.
- Имя папки репо = slug карточки проекта в слое знаний (`knowledge_entity_glob` из `~/.ctx/config.json`). Версии папок суффиксом (`X 2`, `X copy`, `X final`) запрещены.
- `origin` не в `owned_namespaces` → `status: external`, в репо ничего не пишется; заметки хранятся в настроенном слое знаний.
- PR-flow → прямые изменения main ограничиваются настройками GitHub и отдельно настроенной проектной проверкой; kit pre-commit не проверяет branch protection. В solo-проекте коммит в main допустим. `commit` без спроса, `push`/PR/merge/tag — только с разрешения владельца в текущем scope (`commits.md`).
- В корне репо живёт `project.state` (указатели + status + next_action, ≤40 строк). Обновляется на default-ветке после коммита кода; feature-ветка хранит next step в PR. Stop-hook подключается явно.
