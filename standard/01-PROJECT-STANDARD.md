# Стандарт проекта

Стандарт делает проект понятным человеку и AI-агенту. Это практический договор,
а не встроенная функция какого-либо агента. Применяйте только в своих проектах
и адаптируйте масштаб проверки к последствиям изменения.

## Четыре слоя правды

| Слой | Вопрос | Файл |
|---|---|---|
| Смысл | Зачем, для кого, какой результат? | `docs/project.md` или внешняя карточка |
| Состояние | Что активно и что делать дальше? | `project.state` |
| Политика | Как работать, что требует разрешения? | `AGENTS.md` и `rules/` |
| Структура | Где код, входы и границы? | `ARCHITECTURE.md`, контракты модулей |

Один факт — один источник. Полные журналы задач не помещаются в state: state ссылается на них.

## Минимум A

Для любого своего проекта: README, AGENTS.md, компактный state, подходящий `.gitignore`,
правила секретов/изменений/проверки. `CLAUDE.md` и `GEMINI.md` могут быть тонкими обёртками
`@AGENTS.md`; это не доказательство того, что любой runtime разворачивает импорты.
Если runtime не читает их автоматически, агент обязан явно прочитать перечисленные файлы.

## Исполняемый проект B

Добавьте одну команду полной проверки, CI, воспроизводимые зависимости, проверку основного
пути и наиболее важного отказа. Карта структуры — по факту кода, не по названию папок.
Для сервисов отдельно опишите здоровье, deployment target, откат и владельца операции.
Команда локальных тестов не доказывает, что новая версия установлена в production.

## Модульные границы C — дополнительный договор

При необходимости: один публичный вход модуля, принадлежащие ему данные, разрешённые
зависимости, запрет циклов и исполняемый dependency-check в CI. Этот kit не включает
полноценный dependency linter: выберите соответствующий языку инструмент. Не выдавайте
AST-карту за проверку границ. Уровень C не обязателен для первого применения.

## project.state v1.4

YAML-файл в корне, рекомендованный предел — 40 строк. Обязательны:
`schema_version`, `project`, `status`, `updated`, `pointers`, `next_action`.
`project` — kebab-case; `next_action` — один шаг, до 200 символов; `stage` — до 120.
Публичные pointers — относительные пути внутри репозитория. Для внешней базы знаний
поддерживается `knowledge_root`; публичные шаблоны не должны содержать личные пути.
`knowledge_entity` — нейтральное имя; `vault_entity` поддерживается для совместимости.
Имена pointers свободные в snake_case. `head_sha` — якорь проверенного содержимого.

| Статус | Значение |
|---|---|
| idea | Идея, реализация не начата |
| building | В работе |
| live | Работает для пользователей или в runtime |
| maintained | Поддерживается без активного развития |
| paused | Приостановлен |
| superseded | Заменён; нужен `superseded_by` |
| archived | Архив |
| external | Чужой проект; стандарт не даёт права менять его |

Валидатор — подмножество YAML: mappings, простые scalars, списки mappings.
Нет anchors, multiline scalars или произвольных тегов YAML. Проверка наличия paths
и полный JSON Schema-анализ не входят в этот валидатор.

## Один писатель состояния

На основной ветке: коммит содержимого → `project-state-stamp.py` → отдельный коммит state.
На feature-ветке и detached HEAD с origin state не штампуют. Следующий шаг — в PR,
раздел «Дальше». После merge state обновляет один согласованный release-процесс.
Без origin репозиторий считается solo, и stamp допустим на любой ветке.
Если `origin/HEAD` отсутствует, текущий инструмент использует main/master как fallback;
для другого имени сначала выполните `git remote set-head origin -a`.

Свежесть: после `head_sha` не было коммитов, изменяющих что-либо кроме самого state.
Это проверка версии, а не дата сегодняшнего дня и не сертификат качества.

## Правила работы

1. Прочитать AGENTS → state → локальный контракт → задачу.
2. Сначала проверить существующее решение. Не строить дубль из-за нового названия.
3. Согласовать последствия внешних действий по правилам владельца.
4. Сохранять чужие изменения; stage только свои файлы поимённо.
5. Проверить результат свежей командой, указать ограничения.
6. Обновить состояние по правилам ветки. Хуки помогают, но не выдают разрешения.
